## 原生界面检查

已实际启动 arm64 `.app`，检查过：

- 系统文件选择器导入 `examples/示例小说.txt`，书架出现对应条目。
- 书籍右键“章节列表”，列出识别出的前言与四章正文。
- 点击章节进入阅读，进度写入内部索引。
- 悬浮区显示章节、正文及翻页按钮，下一页更新位置。
- 设置页面包含区域尺寸/位置、背景和文字独立颜色与透明度、字号、行距、自动收起及快捷键。
- 输入文字颜色 `#000000` 并失焦，颜色选择器同步为黑色，设置写入磁盘。
- 从应用菜单退出后重新启动，书架条目仍存在。
- 通过 Finder 再次打开正在后台运行的应用，会重新显示书架窗口。

人工截图检查发现 CoreText 与 NSTextView 排版不一致，修正为使用相同 NSLayoutManager / NSTextContainer 测量，并增加 `TestNativePageDoesNotIncludeClippedParagraph`，证明不再把被裁切的第三段计入当前页。

首次系统级按键验证失败。修正为在 Cocoa 事件分发目标注册并处理热键后，用户已用真实键盘确认 Control + Option + H / → 可以使用。不能用“系统注册返回成功”替代这一确认。

用户反馈菜单栏模式打开书后没有独立窗口。后续调整为新安装默认悬浮阅读，书架显示当前模式并提供直接切换按钮；已有用户选择仍保留。菜单栏模式仍直接显示正文，受顶部可用空间约束。

## 实现决定

- 在用户指定的新项目目录内使用 `feat/macos-reader` 分支，没有另建工作树；隔离依靠分支，未改变用户指定位置。
- 实际依赖要求 Go 1.26 及以上，使用已安装的 Go 1.27.4；更旧 Go 未验证。
- 阅读锚点使用 rune；增加 uniseg 字素边界与有界文本片段，避免超长单章阻塞翻页。布局改变后保留锚点，不保存固定页码。
- 核心位置写入同步、原子落盘；界面字段在完成编辑时保存，避免每敲一个字符都写文件。这与计划中的短延迟合并写入有所不同。
- macOS 原生分页及热键路由测试使用实际原生实现；命名与文件组织按职责合并，不逐一创建计划中的同义测试文件。
- 仅在用户要求的范围内提交和推送，不自行合并或创建 PR。
